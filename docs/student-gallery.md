# Student websites gallery: rules for the generator

`student-websites.html` is generated by the scripts in [`tools/gallery/`](../tools/gallery/) (since 28 November 2026; before that, by scripts on the owner's PC). This file is the contract the page must meet.

**Routine after each WhatsApp export:**
1. On the owner's PC: `node tools/gallery/extract.mjs "<export .txt>"` writes `data/gallery/links.json` (links and dates only: no names, numbers or message text). Push it. The chat export itself is never committed.
2. In a Claude Code session: "regenerate the gallery". The session follows [`.claude/skills/student-gallery/SKILL.md`](../.claude/skills/student-gallery/SKILL.md): measure every site, judge the new or changed ones from screenshots (no API key), build, check, open a pull request.

The saved state is in `data/gallery/` (`links.json`, `scores.json`, `anchors.json`, `removed.json`). These files are public; a link a student asks to remove goes in `removed.json` and is skipped from then on. The design is [`docs/superpowers/specs/2026-11-28-student-gallery-generator-design.md`](superpowers/specs/2026-11-28-student-gallery-generator-design.md). `build.mjs` runs the checker itself and writes nothing unless it passes; you can also run it from the repository root:

```bash
node tools/check-student-gallery.mjs
```

It must print `OK: …`. If it lists problems, fix the **generator** (not the HTML by hand) and regenerate. The portal's unit tests run the same check (`cd portal && npm run test:unit`), and the generator's own tests are `cd tools/gallery && npm test`.

## The fix the old generator needed (November 2026)

Two counts were wrong after the 23 Nov regeneration and were corrected by hand in the HTML. The in-repo generator computes them as described here:

1. **Rank among the sites that get a rated card, and only those.** The generator ranked 175 sites but only 171 had scores on the page, so ranks ran up to #175 and every card said "of 175". Build the final list of cards first (after dropping duplicates, removed or offline sites), then rank that list.
2. **Recount the filter chips from the final cards.** The kind-of-site chips kept their old counts (Learning 18, Other 29, Portfolio 38) after 10 sites were added; the real counts were 21, 34 and 39.

The general rule behind both: **every number on the page is computed from the final list of cards, in one place, after that list is complete.**

## Rules

### Cards
- One `<li class="site">` per website, no duplicate links.
- Lovable sites go in `<section id="lovable">`, everything else in `<section id="other">`. In each section, `data-i` runs 0, 1, 2… in order.
- A **rated** site has all five attributes `data-overall`, `data-concept`, `data-uniqueness`, `data-design`, `data-usability`. An **unrated** site (offline or blocking checks) has none of them, no score badge and no rank line.
- The four numbers shown on a rated card (Concept, Uniqueness, Design, Usability) equal its data attributes.
- **Overall = the plain average of the four, rounded half to even** (Python's `round()`: 84.5 → 84, 85.5 → 86).

### Ranks
- Let **R** = the number of rated cards on the page.
- Ranks are **competition ranks among those R sites**, separately for overall and each of the four categories: a site's rank is 1 + the number of rated sites with a strictly higher score. Ties share a rank and the next rank skips (90, 85, 85, 80 → #1, #2, #2, #4).
- Each rated card says `Overall rank <b>#N</b> of R`, and its badge title says `Overall rating S out of 100, rank N of R`.
- Each of the five ranking tables (`#rank-overall`, `#rank-concept`, `#rank-uniqueness`, `#rank-design`, `#rank-usability`):
  - header `R rated sites`;
  - lists all R rated sites, highest score first, each with its rank and its score for that category (matching the card);
  - the first 20 rows are `<li class="rk">`, the rest `<li class="rk more">` (hidden behind "Show all").
- The "How it was scored" text says `Rank 1 is the best of R rated sites`.

### Counts (all from the final cards)
- Intro: `<b>T websites</b>` where T = all cards, and `N on other platforms` where N = cards not on Lovable.
- Section headings: `127 sites` etc. = the cards in that section.
- Platform bar: one segment per platform used, `title="Platform: n"` and width `n / T × 100` to two decimals; the legend shows the same n.
- Filter chips: one per kind of site (`data-cat`), each showing how many cards have it; no chip for a kind with no cards.
- Footer: `Compiled from the Batch 91 chat export of <date>.`

### Shared page parts (from November 27, 2026)
Copy these from `index.html` exactly, so the gallery looks and loads like every other page (the checker compares them):
- the header logo `<a class="site-logo">…</a>`, whose `<source>` tags list `assets/logo-1x.webp 1x, assets/logo-2x.webp 2x, assets/logo-3x.webp 3x` (and the same for `logo-dark-`);
- `<link rel="stylesheet" href="theme.css?v=…">` and `<script src="site.js?v=…" defer></script>`, with the same `?v=` dates as `index.html`;
- **no** Motion `<script>` from `cdn.jsdelivr.net`: `site.js` does the scroll animations itself now. The page loads no script from another site except Google Analytics.

### Elsewhere in the repo
When the total changes, also update (the checker verifies the first two):
- `index.html`: the big number on the Student websites card.
- `README.md`: "Student websites (T sites …)", "A gallery of the T websites students posted (L on Lovable, N on other platforms)", "holds all T cards", and the export date under "Where the content comes from".
- `sitemap.xml`: nothing (the gallery isn't in the sitemap; `robots.txt` keeps it out of search).

### Privacy
Never publish phone numbers, email addresses or poster names from the chat. Titles and descriptions come from each site's own public page; strip any phone numbers or emails a student put on their site.
